# 选题与钩子

先从当前任务确定账号定位、观众、素材、目标和时长。缺少非关键信息时写明假设继续；没有素材就从观众的具体场景生成待验证假设。

## 四问评分
这是一套编辑启发，不是脑科学定律，也不保证流量。每项 0–2 分：0 不清楚，1 部分成立，2 具体且有素材支撑。
- 和我有关吗：观众能认出自己的场景或问题吗？
- 我在乎吗：结果、收益或代价足够具体吗？
- 和我想的一样吗：有真实的新信息或可解释的反差吗？不要为反转编造事实。
- 我能马上看懂吗：开头用熟悉词语，一句话能说明问题吗？

1. 生成 5–10 个候选；从角色、行为、事件或同一需求的具体场景切入。
2. 用表格列出每项分数、总分 /8 和一句理由。按总分排序，同分优先证据更强、拍摄更可行的候选。
3. 为前三名各写一个自然的开头，不强制使用固定句式。用户已指定选题就尊重选择；否则推荐第一名并继续可修改的草稿，无需等待确认。
4. 核对核心事实。使用可核查的一手资料、实测或用户提供的素材；经典著作只是可选解释来源。引用书籍时核对作者、书名、年份及对应段落，不凭年代推定权威，不编造原句。没有证据就删去断言或列为待查证，不让占位事实混入口播成稿。
5. 写六个功能段：开头、具体共鸣、问题后果、原因解释、可执行方法、结尾。允许为时长合并段落，不夸大焦虑；方法尽量为三个具体动作。
6. 需要分镜时交给 [story-research](../story-research/SKILL.md)，照念稿交给 [speak-in-my-voice](../speak-in-my-voice/SKILL.md)。

## 交付检查
输出候选评分、前三钩子、推荐理由、口播草稿、来源与待核实项。检查加总、事实和标题兑现。预计时长标为估计，实测朗读后再确认。不虚构亲身经历、效果数据或平台推荐规则。
